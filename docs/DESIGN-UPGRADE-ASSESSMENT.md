# Game design and component discovery assessment

Reviewed 2026-11-09 before implementation. Existing editor, Codex structured authoring, Docker isolation, artifact hashing and opaque worker preview remain the foundation.

| Source | Actual evidence | Decision |

Prefer coherent CarePlay 2D fruit/basket assets for the current benchmark rather than forcing incompatible 3D/pixel art into the scene. No external assets copied without importing and recording their license/provenance. |

Discovery will search developer-owned trusted metadata first, then compatible adaptation candidates and the explicit external catalog. Functionality, visual suitability, execution boundary, dependency cost, licensing and maintenance evidence influence recommendations. The catalog is a reviewed snapshot, not a live internet crawler or an automatic dependency installer. An allowlisted repository is not approval for arbitrary files, package installation or script execution.

Implement specifically for CarePlay: schema-validated complete game designs; deterministic component discovery; an approved local visual library and visual specification; a data-only lifecycle/geometry/randomness SDK shared by Docker and browser; trusted objective/progress/replay UI; deterministic quality checks and full-lifecycle acceptance probes. Preserve generated-code quarantine. The security validator remains independent from design judgments.

Rosebud's proprietary orchestrator, paid asset models and their results are unavailable locally. A Rosebud account is not required. Screenshots will be inspected during browser verification; the text-only Codex quality path must not claim image inspection.
